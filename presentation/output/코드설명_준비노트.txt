2. 예상 질문과 답변

Q. 왜 LangGraph를 썼나요?
A. 생성 후 검증 결과에 따라 재생성하거나 종료하는 경로를 코드에 명시하려고 사용했습니다. 일반 함수와 if문으로도 가능하지만, 단계별 상태와 실행 기록을 분리하고 요약 경로를 추가하기 쉬운 구조를 택했습니다. 작은 서비스에는 프레임워크 의존성과 학습 비용이 추가되는 단점도 있습니다.

Q. 왜 벡터 DB를 쓰지 않았나요? 그러면 RAG가 맞나요?
A. 검색한 자료를 생성 근거에 넣는 검색 기반 생성 구조입니다. 현재 검색은 BM25 방식의 어휘 검색이며 벡터 DB를 사용하지 않습니다. 설치와 실행을 단순하게 유지할 수 있지만 단어가 전혀 겹치지 않는 표현에는 약합니다. 의미 검색이 필요해지면 임베딩 검색과 결합하고 평가할 계획입니다.

Q. 왜 SQLite인가요?
A. 개인용 로컬 서비스에서 별도 DB 서버 없이 문서, 원문 구간, 대화, 부분 요약을 저장하기 위해서입니다. 다중 사용자 서비스로 확장할 때는 인증과 권한, DB 동시성 등을 다시 설계해야 합니다.

Q. 출처가 있으면 환각이 해결되나요?
A. 아닙니다. 실제 존재하는 ID를 인용했는지와 퀴즈 형식은 검사하지만, 문장이 원문으로부터 타당하게 도출되는지는 보장하지 않습니다. 실제 역할 혼동 사례도 발견했습니다. 정답 데이터 기반 평가가 다음 과제입니다.

Q. 전체 요약이 100% 정확해졌나요?
A. 60개 구간을 모두 부분 요약 단계에서 처리하게 됐다는 뜻입니다. 최종 요약에는 생략이나 오류가 남을 수 있습니다. 처리 범위와 답변 정확도는 구분했습니다.

Q. 캐시가 있는데 자료가 바뀌면요?
A. 키에 원문 내용과 모델 정보를 넣어 변경 시 다른 키를 사용합니다. 프롬프트 변경 시에는 요약 버전도 갱신해야 합니다.

Q. 테스트 33개가 의미하는 것은 무엇인가요?
A. 선택 자료 범위 분리, 업로드 제한, 저장 유지, 잘못된 인용의 재시도와 원문 반환, 모델 응답 처리, 전체 구간 요약과 캐시 등을 확인한 코드 테스트입니다. 모델 답변 정확도 100%를 의미하지 않습니다. OpenAI 실제 호출은 별도로 자체 샘플에서 확인했습니다.

Q. Multi-Agent나 MCP를 구현했나요?
A. 이번 프로젝트는 LangGraph 기반 단일 워크플로입니다. Multi-Agent, MCP, LangSmith는 구현하지 않았습니다. 실제 사용한 기술과 검증 가능한 기능 위주로 설명합니다.

3. 발표 직전 확인
- 사용할 PPT는 이름에 코드설명형이 포함된 개정본이다.
- 본문 전체를 읽지 말고 슬라이드 4의 모델 주입, 5의 재시도 조건, 6의 부분 요약을 중심으로 설명한다.
- 실제 코드를 열 경우 위 함수 이름을 검색한다. .env 파일이나 API 키는 화면에 띄우지 않는다.
- AI 도움으로 작성한 코드도 직접 검토하고 실행·테스트한 범위에서 설명한다. 직접 작성하지 않은 부분을 수작업으로 전부 작성했다고 말하지 않는다.
